Облачная серия завершена, все заданные критерии выполнены в исследованных условиях.
[Итоговый отчёт и графики](../YANDEX_CLOUD_H3_INCREMENTAL_20261003.md).
Временные ресурсы удалены; дампы и исходные результаты сохранены и проверены.

Новый backend worktree: `worktrees/h3-incremental/firefly-backend`, ветка
`thesis/20261003-h3-incremental`, база `d1e1bdc`.
Новый модуль `app/modules/commander/analytics_incremental.py` устанавливается
только в отдельную экспериментальную БД. В основные репозитории изменения
не переносятся; обычный endpoint приложения сохраняет прежнее поведение.

[PLAN.md](PLAN.md) задаёт матрицу, критерии до измерений и ограничения вывода.
Четыре варианта возвращают одинаковую аналитику на клонированных исходных данных.
Две проекции используют одну и ту же читающую часть; SQL-варианты рассчитывают
ответ по исходным таблицам.
У кандидата очередь по `CrewMemberAssessment`, отдельная очередь изменений тренировок,
транзакционное объединение ключей и UPSERT только изменившихся фактов.
Исполнители сериализуются advisory lock; горизонтальное масштабирование worker
этой реализацией не исследуется.

Проверенный пакет: `results/yc-h3i-bundle-20261003-v1`.
Локальная проверка: `results/h3-local-validation-20261003-final-v1` — 29 сценариев,
406 сравнений ответов, полная сверка фактов/оценок, 32 проверки первоначального

Ошибок нет; это функциональные проверки, не облачные оценки производительности.

Новый облачный запуск: `results/yc-h3-incremental-20261003-a`.
Предыдущие результаты `yc-h3-20261003-b` и их seal не меняются.

```bash
python3 -m cloud.bundle --backend worktrees/h3-incremental/firefly-backend \
  --purpose 'H3 incremental experiment' --output results/НОВЫЙ_ПАКЕТ
python3 -m h3.local_smoke results/НОВЫЙ_ПАКЕТ --output results/НОВАЯ_ПРОВЕРКА
python3 -m h3.ops provision results/НОВЫЙ_ЗАПУСК
python3 -m h3.ops watchdog results/НОВЫЙ_ЗАПУСК
python3 -m h3.run setup results/НОВЫЙ_ЗАПУСК --bundle results/НОВЫЙ_ПАКЕТ
python3 -m h3.run smoke results/НОВЫЙ_ЗАПУСК
python3 -m h3.run main results/НОВЫЙ_ЗАПУСК
python3 -m h3.run finish results/НОВЫЙ_ЗАПУСК
python3 -m h3.ops cleanup results/НОВЫЙ_ЗАПУСК
python3 -m h3.analyze results/НОВЫЙ_ЗАПУСК
python3 -m h3.costs results/НОВЫЙ_ЗАПУСК
python3 -m h3.export_monitoring results/НОВЫЙ_ЗАПУСК
python3 -m h3.resource_report results/НОВЫЙ_ЗАПУСК
python3 -m h3.cost_report results/НОВЫЙ_ЗАПУСК
python3 -m h3.dashboard results/НОВЫЙ_ЗАПУСК завершён
python3 -m h3.seal results/НОВЫЙ_ЗАПУСК
```

Watchdog запускается отдельным локальным процессом одновременно с работой стенда.
`setup` проверяет реальное выключение генератора через systemd service и сохранение
абсолютного срока после старта. Исходящий SSH-адрес оператора может отличаться от
HTTPS-адреса; разрешены только необходимые /32. В фактическом запуске публичный
адрес сервера не отвечал по SSH, поэтому сервер администрируется через генератор.
В `resources.json` это `server_ssh_via_loadgen=true`, обратный маршрут выключен.
HTTP-нагрузка всегда идёт по частной сети и не зависит от административного SSH.

Артефакты фиксируют локальные изменения контроллера после упаковки: выбор SSH relay,
таймаут SSH для 84 смешанных сценариев, анализ/учёт расходов. Измерительный код
на ВМ остаётся из пакета; хеши всех файлов проверяются до и после основной серии.
Расширенный таймаут не отменяет шестичасовой остановки ВМ.
После измерений `finish` дополнительно сохраняет физические размеры таблиц и
приближённые счётчики изменений PostgreSQL, настройки и метаданные pg_stat_statements.
Вне измеряемых окон обе проекции полностью сверяются с исходными таблицами
через EXCEPT ALL в обоих направлениях, включая указатели последних оценок.
Это диагностическое чтение вне окон
измерения. Локальный анализ сохраняет также p50 и задержки от планового поступления;
он не меняет заранее зафиксированные критерии.

До основной серии применён документированный overlay `cloud/guest_metrics.py`:
выбор контейнеров по наличию Compose-метки вместо имени прежнего проекта.
Он охватывает новый серверный проект и контейнер генератора. Исходный и новый
файлы, хеши и подтверждение применения на обеих ВМ находятся в
`overlays/telemetry-discovery` и `runtime-overrides.json`. Проверка 496 файлов
на каждой ВМ учитывает только это объявленное изменение; расхождений перед
основной серией нет. Измерительные модули и backend не изменены после упаковки.

`finish` останавливает worker, копирует пять дампов, проверяет TOC и полностью
восстанавливает БД кандидата в пустую БД, сравнивая число строк восьми ключевых таблиц.
После копирования проверяются SHA-256. Удаление временных ресурсов требует маркера
успешной проверки копии. После seal нельзя запускать команды, дописывающие в архив.

Billing относится к каталогу за день/дни и включает предыдущую серию: исходное
наблюдение сохраняется отдельно. Разность наблюдений может включать запоздавшие
начисления первого запуска. Оценка VM+SSD+IP относится только к новым ВМ.
Снижение WAL или CPU не объявляется экономией фиксированной аренды.
