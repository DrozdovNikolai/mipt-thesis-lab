## Подготовленная автоматизация

- [cloud_preflight.py](h2/cloud_preflight.py) — чтение квот, Billing,
  тарифов и инвентаря. Добавлена поддержка зональных квот; лимит другой
  зоны не используется вместо лимита выбранной зоны.
- [cloud_ops.py](h2/cloud_ops.py) — отдельные ресурсы и группы узлов,
  журнал операций, собственный kubeconfig, проверка владельца ресурса,
  остановка и удаление после проверки резервных копий.
- [cloud_setup.py](h2/cloud_setup.py) — публикация закреплённого образа
  в отдельном реестре, установка KEDA и таймера остановки кластера.
- [cloud_trial.py](h2/cloud_trial.py) — отдельная очередь каждого прогона,
  исходные наблюдения ВМ/дисков/pod, метрики ресурсов, экспорт SQLite
  и независимая проверка резервной копии.
- [cloud_pilot.py](h2/cloud_pilot.py) — облачные ASR-эталоны, повторяемость
  результатов, калибровка длительности стадий только на `pilot`-аудио,
  три проверки холодного старта и наблюдение автоматического удаления узла.

**Облачные ветки этих новых модулей пока не проверены на развёрнутом
стенде.** Реальный запуск дошёл только до проверки квот и корректно
завершился с `Insufficient quota; no resource created`. Это не облачный
бенчмарк и не подтверждение работоспособности всех операций управления.

## Локальная проверка

**17 тестов прошли**: очередь и fencing, денежный учёт, знаменатели SLO,
зональные квоты и аудит резервных копий. Синтаксис новых модулей проверен.

Проверка повреждённых копий выявила важный случай: SQLite в режиме
`immutable` не читает оставшиеся изменения из WAL. Экспорт теперь явно
завершает запись в основной файл; аудитор отклоняет копию с непустым WAL.
Дополнительно проверяются пропавшее задание, повторное принятое завершение
и JSON результата, не соответствующий сохранённому хешу.

```bash
python3 -m pytest --noconftest -q \
  h2/test_cloud_costs.py h2/test_cloud_preflight.py \
  h2/test_cloud_backup.py h2/test_queue.py
```

## Что остаётся

После одобрения квот — облачное развёртывание и проверка остановки стенда,
затем пилот. По его результатам нужно настроить baseline по длине очереди,
зафиксировать основную матрицу и численные критерии, провести сравнение
`fixed / count / work`, собрать Billing по ресурсам, дашборд и графики.
Основной драйвер серии и итоговый анализ завершаются после получения
реальных данных пилота. H2 пока нельзя считать проверенной в облаке.
Фонового развёртывания во время ожидания квот нет. Перед возобновлением
проверяются статус заявки, актуальность тарифов и инвентарь каталога.
