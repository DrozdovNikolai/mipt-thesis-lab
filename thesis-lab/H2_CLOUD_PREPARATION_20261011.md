# H2: продолжение подготовки облачной проверки, 11.10.2026

**Основная облачная серия H2 ещё не выполнена. Новые облачные ресурсы
не создавались.** При чтении списка ВМ профиль `firefly-thesis` снова
запросил интерактивную авторизацию владельца. Предыдущий вход нельзя
считать действующим без успешного ответа API.

Результаты локального Kubernetes/ASR за 05.10.2026 остаются в
[отдельном отчёте](H2_LOCAL_READINESS_20261005.md). Они не используются
как доказательство рублёвой экономии в Yandex Cloud.

## Что подготовлено сейчас

- [cloud_preflight.py](h2/cloud_preflight.py): подготовлен сбор сведений
  о версиях Kubernetes, доступных квотах, текущих ресурсах, тарифах SKU
  в рублях и потреблении всего платёжного аккаунта с даты снимка гранта.
  Скрипт выполняет только чтение. Его обращения к облачным API ещё
  не проверены: действующая авторизация отсутствует. Проверка синтаксиса
  выполнена. Скрипт отдельно оставляет проверку квоты Kubernetes,
  выбор текущих SKU и расчёт допустимого бюджета; автоматически считать
  стенд готовым к платному запуску по одному успешному входу нельзя.
- [cloud_costs.py](h2/cloud_costs.py): добавлен учёт времени выделения
  ВМ и дисков по полным последовательным снимкам отдельного прогона.
  Время исчезновения ресурса задаётся интервалом между последним
  присутствием и первым отсутствием, а не выдуманной точной секундой.
  Ошибочный опрос не считается пустым списком ресурсов. Оставшийся диск
  продолжает учитываться после удаления ВМ. Остановка ВМ требует
  отдельного учёта интервалов; такой случай не маскируется обычной формулой.
- Доля результатов в срок использует все принятые задания. Ошибочные,
  неподтверждённые эталоном, поздние и незавершённые результаты не
  исключаются ради лучшего показателя. Расчётные затраты не выдаются
  за фактические начисления Billing.
- Сохранён исходный снимок HEAD, git status и хешей отслеживаемых файлов
  четырёх основных репозиториев. Изменения этой сессии находятся в лаборатории.
  Итоговая сверка подтвердила совпадение всех трёх показателей для backend,
  instructor, commander и session.

## Проверки

Команда:

```bash
python3 -m pytest --noconftest -q h2/test_cloud_costs.py h2/test_queue.py
```

Результат: **9 тестов прошли**. Шесть проверяют денежный учёт и знаменатели
метрик, три — конкурентный приём/выдачу задач, lease/fencing и восстановление
очереди. Это проверки кода стенда, а не новые облачные эксперименты.

Артефакты этой подготовки:
[results/h2-cloud-preparation-20261011-a](results/h2-cloud-preparation-20261011-a).
Архивы предыдущих H1/H3 и H2 от 05.10 не изменялись.

## Следующие шаги после входа

1. Выполнить сбор текущих сведений и проверить реальные квоты, цены,
   расходы аккаунта и доступный бюджет. Баланс аккаунта не приравнивается
   к остатку рекламного гранта; старый снимок 3700 ₽ сам по себе не
   подтверждает сегодняшний остаток.
2. Завершить облачный драйвер: создание отдельных групп узлов,
   ограничение длительности работы, сбор метрик и исходных результатов,
   проверка резервной копии и удаление ресурсов только этого эксперимента.
3. Провести облачный пилот холодного старта и длительности обработки,
   настроить baseline по длине очереди на отдельной нагрузке.
4. До основной серии сохранить окончательную матрицу, число повторов,
   критерии стоимости/своевременности, seed и хеши конфигурации.
5. Сравнить `fixed`, `count`, `work` на одинаковых входах. Сохранить
   историю реально выделенных ВМ, отдельные общие расходы кластера,
   графики Monitoring и начисления Billing по идентификаторам ресурсов.

Протокол и ограничения:
[CLOUD_PROTOCOL_DRAFT.md](h2/CLOUD_PROTOCOL_DRAFT.md).

Если ссылка текущего входа перестала работать, новую можно получить
в том же WSL следующей командой; токены в чат передавать не требуется:

```bash
yc --profile firefly-thesis --no-browser compute instance list
```

Источники, просмотренные при продолжении подготовки:

- [Тарификация Managed Kubernetes](https://yandex.cloud/ru/docs/managed-kubernetes/pricing):
  мастер и вычислительные узлы учитываются отдельно; остановка кластера
  не отменяет плату за оставшиеся связанные ресурсы.
- [Создание кластера](https://yandex.cloud/en/docs/managed-kubernetes/operations/kubernetes-cluster/kubernetes-cluster-create).
- [KEDA Metrics API 2.18](https://keda.sh/docs/2.18/scalers/metrics-api/):
  используется та же версия интеграции, что в локальной проверке.
- Локальная справка YC CLI 1.39.0: ConsumptionCore ограничен одним
  запросом в минуту на IP. Поэтому подготовка запрашивает один общий
  отчёт потребления, а не запускает несколько запросов Billing параллельно.
