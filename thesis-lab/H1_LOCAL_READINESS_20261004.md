# H1: локальная проверка и готовность облачного эксперимента

Дата: 4 октября 2026 года. **Локальные проверки завершены; основная серия в
Yandex Cloud ещё не выполнена. Гипотеза пока не объявляется подтверждённой.**
YC CLI запросил повторную интерактивную авторизацию профиля `firefly-thesis`.
Новые облачные ресурсы для H1 не создавались, новых расходов на них нет.

## Предмет проверки

Проверяется доставка тренировки до сохранения проверенной финальной квитанции
на клиенте: события состава экипажа, оценки, наблюдения, терминальное состояние
упражнения и неизменяемое намерение завершения. Сравниваются три варианта:

| Вариант | Доставка |
|---|---|
| `split_full` | События и полный черновик отдельными запросами |
| `split_compact` | События и компактное состояние отдельными запросами |
| `unified_compact` | События и компактное состояние в общей транзакции |

У всех вариантов одинаковые локальная очередь SQLite, правила повторов и
проверка квитанции. Это позволяет отдельно оценить эффект сокращения данных
и эффект объединения запросов. Используются настоящие API Firefly и PostgreSQL.
Python-драйвер сравнивает протоколы; отдельный браузерный сценарий проверяет
Flutter и IndexedDB. Нагрузка браузерного сценария отличается от протокольной,
его результаты не объединяются с основной сравнительной матрицей.

Подробный план и критерии зафиксированы до основной облачной серии:
[h1/PLAN.md](h1/PLAN.md).

В протокольной матрице проверены offline с аварией клиента, потеря ответа sync
после commit, потеря ответа submit после commit, авария клиента перед локальным
сохранением квитанции и авария backend перед commit. Последний сценарий прерывает
реальный процесс; до его перезапуска отдельное соединение PostgreSQL проверяет
откат. По каждой тренировке сохранены очередь, попытки, сетевые байты, результаты
API и независимая сверка событий, оценок, наблюдений и статуса в БД.

Браузер убивается принудительно, без предварительного штатного закрытия.
В шести проверках writer ID дополнительно очищается только legacy localStorage;
IndexedDB остаётся. Проверяется сохранение замороженного намерения и оценок.
После потери submit-ответа восстановление вправе получить квитанцию через status
GET без повторного POST. Тестовая авторизация восстанавливается драйвером;
устойчивость пользовательской OAuth-сессии этим не проверяется.

Выбранные тесты backend прошли в нескольких запусках: 9 существующих проверок,
23 проверки расширенной выборки и отдельно исправленная новая регрессия.
Наборы пересекаются, эти числа не суммируются. В расширенном запуске первоначально
ошиблось ожидание теста `detail.code`: API возвращает `error.code`; исправленный
тест прошёл. Последние Flutter-прогоны: 33 проверки writer/recovery/submit/sync
и 61 проверка архитектуры сессии; ранее также прошёл набор из 73 проверок,
пересекающийся с ними. Web-сборка завершилась успешно; анализ новых файлов
writer identity не обнаружил замечаний. Это целевые проверки, а не весь набор
тестов четырёх приложений. [Логи, включая отрицательные](results/h1-readiness-20261004/logs).

Это **одно наблюдение на условие на общей локальной машине**. Во время подготовки

но не TCP/IP/TLS. Gzip сжимает ответы. Все шесть оценочных состояний доставляются

## Найденные ошибки и изменения

1. **Writer ID свежего браузера.** Идентификатор перенесён в отдельную IndexedDB
   с ожиданием завершения strict-транзакции под существующей блокировкой origin.
   Существующий идентификатор мигрирует; он не восстанавливается из чужого черновика.
   Нативное secure storage сохраняется. Проверка аварии процесса не доказывает
   сохранность при отключении питания или очистке всего профиля.
2. **Повторное создание завершённого черновика.** После принятия `COMPLETED`
   через status GET восстановление теперь завершается сразу: старый UI snapshot
   больше не записывает очищенный draft/outbox заново. Добавлена регрессия.
3. **Молчаливый пропуск неизвестной компетенции.** Backend отклоняет непустую
   оценку с неизвестным кодом и откатывает submit вместо выдачи успешной квитанции
   с неполными оценками. Тест проверяет отсутствие seal/receipt/оценок и успешный
   следующий корректный submit. Исправление общее для трёх вариантов и не считается
   преимуществом только unified.

Первые неудачные пилоты сохранены отдельно: `results/h1-smoke-20261004-a`…`-d`
и `results/h1-browser-20261004-b`…`-d`. Они включают ошибки подготовки стенда,
тестового драйвера и описанные ошибки приложения. Исправлены неверный код
компетенции в fixture и восстановление черновика. Нестабильный Flutter-тест
Retry-After сохранён в исходных логах; проверка запрета ранней доставки осталась,
после дедлайна добавлен ограниченный опрос вместо одного зависящего от времени вызова.
Успешные серии не заменяют и не скрывают предыдущие результаты.

## Что остаётся выполнить в Yandex Cloud

Основная серия: 768 тренировок, 8 технических блоков, по 256 случаев на вариант,
рандомизация порядка. Две отдельные ВМ для приложения/БД и генератора нагрузки,
без конкурирующих локальных тестов. Предварительно объявленные критерии: уменьшение
времени и байтов в основном профиле по верхней границе парного bootstrap 95% CI,
проверка корректности и допустимого ухудшения доли завершений в 2 процентных пункта.
Оценка долей условна относительно независимости испытаний; технические повторы
на общих ВМ не дают гарантии production SLA. p95 восьми наблюдений — описательная оценка.

Подготовлены сбор CPU/RAM/сети и метрик контейнеров, H1-дашборд Monitoring,
выгрузка Billing в рублях, проверка автоостановки, дамп с восстановлением и удаление
временных облачных ресурсов после проверки копий. Эти облачные действия для H1
пока не выполнены. Графики этого отчёта получены локально, это не графики YC.

План ресурсов: 8 vCPU / 16 GiB / 128 GiB SSD для сервера и
2 vCPU / 4 GiB / 32 GiB SSD для генератора. Плановая оценка по записанным тарифам —
22,71 ₽/ч за ВМ, SSD и два IPv4, около 136,27 ₽ за предельные 6 часов;
Monitoring и дополнительные услуги отдельно. Текущий остаток гранта не проверен.
Рубли относятся ко всему стенду: сокращение трафика не снижает автоматически
цену фиксированной ВМ. Перед созданием ресурсов нужен свежий preflight.

Чтобы восстановить доступ, владелец аккаунта выполняет в WSL и завершает вход
по выданной CLI ссылке:

```bash
yc --profile firefly-thesis --no-browser compute instance list
```

Токены в чат не нужны. Следующий этап после входа — свежая проверка доступа,
квот и ресурсов, затем развёртывание сохранённого пакета и облачная серия.
