# Протокол экспериментов Firefly

Пилотные и основные результаты хранятся отдельно. Основная серия выполняется
по зафиксированному MAIN_SERIES_PLAN.md; завершение отмечается complete.json.

## Изоляция и происхождение

Четыре репозитория, по baseline/candidate worktree. В исходных индексах и
ветках изменений не выполняется. Исходные коммиты, хеши файлов и исключённые
операционные файлы записаны в provenance/sources.json. Baseline включает
актуальные локальные исправления; это контрольный вариант, а не имитация
исторического релиза. HTTP baseline использует существующие legacy endpoints.
Compose имеет собственную внутреннюю сеть и две отдельные тестовые БД;
внешние API, рабочие БД, брокеры и секреты не используются.

## Гипотезы и границы вывода

H1: split runtime + full assessment draft против unified runtime + compact
assessment v2. Одинаковые доменные действия, очередь и политика повторов.
Основные показатели: байты JSON request/response bodies (не Ethernet/TLS),
число запросов, время доставки, корректность восстановления. В каждом
прогоне проверяется финализация; сохранённый draft не считается финализацией.
Разделить compact-only и combined эффекты дополнительным вариантом.

H2: штатные поэлементные CRUD операции против штатного versioned snapshot.
Измерять частичное применение логической операции, обнаружение конфликтов,
время и байты сохранения при одинаковом конечном контенте. Локальная очередь
редактора проверяется отдельно существующим JS harness и дополнительными
сценариями. Серверная атомарность не приписывается одной только очереди.

H3: текущий endpoint распределения оценок компетенций против той же функции
с аналитической проекцией. Сохранять семантику latest assessment, latest grade,
исторического asOfDate и tenant/user/aircraft/age/position фильтров. Проверять
исправления, смену статуса и удаления, повторную доставку, откат транзакций,
перезапуск обработчика, полный rebuild. Оценить свежесть и размер проекции.

## Методика

Настоящий TCP HTTP к Uvicorn + PostgreSQL; отдельные интеграционные тесты могут
использовать ASGITransport, что явно отмечается. Фиксированные seed, прогрев,
чередование порядка baseline/candidate по seed. Последовательные эксперименты;
нагрузка внутри одной серии может быть конкурентной. Сохранять каждый замер,
ошибки, конфигурацию и размеры данных. p50/p95/p99 описательные; bootstrap CI
считать по независимым повторным сериям, не по коррелированным запросам.

После пилота зафиксировать план основной серии до её запуска. Нулевая частота
потерь в конечной выборке не доказывает невозможность потери; при недостаточной
выборке для non-inferiority писать «не установлено», не «подтверждено».
Не подбирать число повторов под желаемую значимость.

Синтетические сбои сети/процессов ограничены явно перечисленными точками.
Физические мобильные устройства, выключение питания, разрушение диска и
полноценный production capacity/SLA не входят в автоматический стенд.
