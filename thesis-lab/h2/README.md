В отличие от исторического локального H2 по редактированию сценариев,
эта работа проверяет текущую гипотезу о масштабировании. H1/H3 и их
запечатанные архивы не изменяются.

План подготовки:
1. Готовый CPU ASR Firefly (`speech_whisperx`, WhisperX/Silero, tiny.en),
   одинаковая модель во всех вариантах; контролируемый синтетический звук.
2. Сохраняемая очередь с lease, fencing устаревших завершений и повтором
   после падения worker; оценка оставшейся работы по стадии и длине аудио.
3. Kubernetes/KEDA: фиксированный пул, настроенная стратегия числа заданий,
   контроллер оставшейся работы. Общие ограничения, FIFO и защита in-flight.
4. Отдельные пилоты: время CPU обработки/загрузки модели/запуска узла,
   настройка baseline до заморозки основной матрицы и критериев.
5. Реальное изменение числа оплачиваемых узлов; жизненный цикл каждого
   ресурса, Billing до гранта, общие расходы отдельно. Pod-seconds и CPU
   utilisation сами по себе не являются рублёвой экономией.
6. Сырые данные, проверки результатов, авария pod, Monitoring и локальные
   графики, резервная копия, удаление только собственных облачных ресурсов.

CPU результаты не обобщаются на GPU, диаризацию и полную AI-оценку тренировок.
Готовность ASR проверяется по совпадению с последовательным эталоном той же
модели; это проверка сохранения результата, а не качества распознавания речи.
При недостаточном эффекте гипотеза не будет объявлена подтверждённой.

Первичная настройка:

1. В Cloud.ru откройте **Пользователи → Сервисные аккаунты → Создать аккаунт**.
   Имя — `firefly-thesis-bench`, уровень — **Проект**, проект — созданный для
   экспериментов. Назначьте роль **Администратор проекта**
   (`platform.project.admin`) только в этом проекте.
2. В карточке аккаунта откройте **Учетные данные доступа → Ключи доступа →
   Создать ключ**. Для исследования можно задать срок 30 дней.
   Сохраните выданные **Key ID** и **Key Secret** до закрытия окна.
   Требуется именно ключ доступа с этой парой значений.
3. Скопируйте UUID проекта: список проектов в верхней панели → меню `⋮`
   нужного проекта → **Скопировать ID проекта**.
4. В локальном терминале WSL выполните:

   ```bash
   python3 /mnt/c/dev/startup/projects/firefly-thesis-lab/h2/cloudru_access.py
   ```

   Введите Project ID, затем Key ID и Key Secret. Оба поля ключа вводятся
   скрыто. Ключи не нужно отправлять в чат или помещать в командную строку.

Скрипт сохраняет профиль в
`~/.config/firefly-thesis/cloudru/credentials.json` (файл `600`, каталог `700`)
в файловой системе WSL вне репозиториев и архивов результатов. Это локальный
файл с секретом, а не зашифрованное хранилище. При повторном запуске скрипт
отказывается перезаписывать существующий профиль. Для проверки сохранённого
доступа используется:

```bash
python3 /mnt/c/dev/startup/projects/firefly-thesis-lab/h2/cloudru_access.py --check
```

Проверка обращается только к IAM за временным токеном, не сохраняет и не
выводит его, не создаёт платные ресурсы. Успешный ответ подтверждает
аутентификацию ключа, но сам по себе не подтверждает права на указанный
проект, квоты или доступ к Billing. Их проверка и оценка полной стоимости
предшествуют развёртыванию. По документации роль администратора проекта
позволяет читать потребление своего проекта через Billing API.
