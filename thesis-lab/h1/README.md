# H1 — проверка устойчивого завершения тренировок

Облачная серия завершена: 768/768 корректных завершений, все объявленные критерии выполнены.
[Итоговый отчёт](../YANDEX_CLOUD_H1_DURABLE_20261004.md). Временные облачные ресурсы удалены.
План: [PLAN.md](PLAN.md). Основные checkout не изменены.
Реализация — `../worktrees/h1-durable/firefly-backend` и `firefly-instructor`.

Изменения приложения:

- Browser writer identity: отдельный IndexedDB, ожидание strict commit, миграция
  существующего writer, origin-wide lock. Нативный secure storage сохраняется.
- Restore после принятия COMPLETED receipt не пересоздаёт старый draft/outbox.
- Backend отклоняет неизвестный непустой код компетенции вместо пропуска оценки
  при выдаче квитанции. Это общий контроль корректности для всех вариантов.

Измерения выполняются настоящими API/PostgreSQL. SQLite Python-driver используется
для сравнения протоколов, Flutter/IndexedDB отдельно проверяется в Chromium.
Условия аварии фиксируются в JSONL; отсутствие uncommitted изменений после аварии
backend проверяется до перезапуска отдельным SQL-соединением.

Локальный Compose: `compose.local.yml`; только собственный проект
`firefly-thesis-h1-20261004`, порты 14700/14701, HTTP harness 14702.
Не запускать протокольный и браузерный прогон одновременно: они разделяют
прокси управления сетью и тестового инструктора.

Облачный запуск использует новый пакет `h1.bundle`, `h1.ops`, `h1.cloud_run`.
Не запускать cloud.run/h3.run для H1 и не менять запечатанные архивы H3.
Развёртывание допускается после локальных проверок и доступной авторизации YC.

Переносимый пакет можно проверить без облака:

```bash
python3 -m h1.local_smoke results/yc-h1-bundle-20261004-v2 \
  --output results/h1-portable-smoke-НОВЫЙ_ID
```

Проверка отказывается использовать существующий контейнер/том своего проекта,
не пишет в исходный пакет и удаляет только свои локальные ресурсы.

YC CLI может повторно запросить интерактивный вход после истечения сессии.
Команда без вывода токенов: `yc --profile firefly-thesis --no-browser compute instance list`.
Авторизацию завершает владелец аккаунта. Пока она не завершена, ВМ не создаются.
