# Восстановление реплик и переменных полей чек-листов

Назначение: подготовить дополнительные слабые train-пары из тех же девяти
английских записей BLeRIOT. Это не обучение адаптера и не оценка качества ASR.
Старые исходные файлы, разметка и результаты не переписываются.

## Исходные данные

Используются 675 сохранённых клипов `pair-quality-v1`, старые small/English
ответы и medium.en ответы `publisher-phrases-v2`. Прежние 96 принятых пар
сохраняются в новом train с теми же текстами и аудио. Кандидаты создаются только
из остальных 579 клипов, поэтому новые пары не перекрывают эти 96 по времени.
Говорящие/сессии/записи сохраняют train-раздел. Прежние 35 dev-пар копируются
побайтно, без отбора по ним. Test не используется.

## Генерация кандидатов

Нормализация применяется только для поиска и сравнения. Она сохраняет связь
каждого токена с исходным словом и его таймкодом; раскрытое сокращение нельзя
разрезать посередине. Целевой текст остаётся соединением неизменённых слов
medium.en либо прежним полным ответом для целого клипа. Новые слова из PDF
в целевой текст не дописываются.

Предлагаются:

- Непрерывные участки минимум из четырёх нормализованных слов, точно совпадающие
  у small и medium.en и в издательском документе.
- Семь явно описанных числовых полей A320 pilote: топливо, барометрическая
  установка, скорости/тяга, триммирование, конфигурация закрылков, высота FCU,
  минимум. Значения берутся только из аудиоответов; PDF подтверждает наличие
  поля, но не его значение. Сохраняются поверхность и последовательность чисел.
- Ответы обоих участников для окон и управления полётом, формы объявления
  начала/завершения разделов. Такие формы указаны отдельно от буквального текста PDF.
- Целые клипы из старой очереди исключительно документальных отказов, если
  раскрытие сокращений даёт поддержку ≥90% и поддерживает критические токены.
  Старые проверки согласия моделей для этой ветви не ослабляются.

Формы и источник PDF закреплены в `configs/publisher_slots_v3.json`. Структуру
страницы проверил ассистент по изображению в предыдущем разборе. Никакое поле
не заполняется по «правдоподобному» авиационному значению.

Для вырезаемых реплик требуются допустимые таймкоды, медиана вероятностей слов
каждой исходной модели ≥0.6 и не более 25% слов с нулевой длительностью. Граничные
слова должны иметь положительную длительность; расхождение двух оценок начала
и конца ≤0.45 с. Допускается 0.15 с запаса с каждого края. Длительность клипа
1.2–25 с. Части числовой последовательности и прилегающие пропущенные отрицания
не вырезаются отдельно.

Внутри каждого исходного клипа выбирается максимальная по длительности цепочка
неперекрывающихся реплик с неубывающими позициями в документе. Переход между
документами допускается. Это локальная проверка порядка; глобальная привязка
всей длинной записи к сценарию здесь не реализована. Повторы целого чек-листа
не запрещаются искусственно между разными исходными клипами.

До новых распознаваний получено 514 кандидатов из 361 исходного клипа:
471 буквальный участок, 21 целый клип с сокращениями, 15 объявлений разделов,
3 числовых поля и 4 повторных ответа. Целые клипы и части могут перекрываться
среди кандидатов; после проверки выбирается неперекрывающийся набор.

## Повторная проверка вырезанного аудио

Каждый из 514 клипов заново распознаётся двумя моделями:

- исходная `whisper-medium-en-ct2`;
- исходная многоязычная `whisper-large-v3-systran-ct2` с явным языком English.

Список заданий содержит только идентификатор, путь, длительность и хеш аудио.
PDF, кандидатные тексты и старые ответы не подключены к контейнеру inference.
Конфигурация шаблонов доступна коду для проверки её хеша; в ASR-вход она не
передаётся. Фактические параметры каждого вызова сохранены вместе с ответом.
Сеть отключена; GPU 0, float16, beam 5, контекст предыдущего текста выключен,
prompt/prefix/hotwords отсутствуют. План и хеши кода закреплены до запуска.

Ответ свежей medium.en должен точно совпасть с кандидатом после нормализации
поиска. У large-v3 требуется точное совпадение для текстов короче восьми слов;
для остальных разрешено ≤10% расхождения. Последовательности чисел и состояний/
отрицаний должны совпасть точно в обеих проверках. Вновь проверяются вероятности
и временные интервалы слов. Добавленные или пропущенные medium слова означают
отказ: это, в частности, удерживает клипы с неудачной границей вырезания.

Повторная medium использует те же веса; large-v3 принадлежит тому же семейству
Whisper. Эти проверки не являются независимой человеческой разметкой и не
устанавливают истинную ошибку чисел. Все новые тексты остаются `weak`.

## Экспорт и использование

После проверки вновь выбирается неперекрывающаяся цепочка из прошедших кандидатов.
Экспортируются `train.jsonl`, только новые пары в `added.jsonl` и прежний `dev.jsonl`
в `data/curated/publisher-recovery-v3`. Хеши аудио и декодированного сигнала,
источник сценария, исходные координаты, обе прежние и обе свежие ASR-проверки
записываются в происхождении пары.

Политика `publisher_template_recovery_v3` допускает смесь прежних v2 и новых v3
слабых пар, требует свежие проверки v3 и не допускает их использования как
human_verified или свидетельства качества. Прежняя v2 политика новые записи
не принимает. Предыдущие 49 двадцатисекундных окон в эту смесь не добавляются
автоматически; дополнительное покрытие относительно них рассчитывается отдельно.

Воспроизведение:

```powershell
docker compose -f compose.publisher-recovery-v3.yaml run --rm prepare
docker compose -f compose.publisher-recovery-v3.yaml run --rm infer infer --system medium
docker compose -f compose.publisher-recovery-v3.yaml run --rm infer infer --system large
docker compose -f compose.publisher-recovery-v3.yaml run --rm assemble
```

Подготовка и экспорт не перезаписывают существующую версию. Повтор завершённого
infer проверяет хеши, не выполняя новых ASR-вызовов. Правила не меняются после
просмотра новых ответов. Результат не закрывает требования качества полного SPEC.
