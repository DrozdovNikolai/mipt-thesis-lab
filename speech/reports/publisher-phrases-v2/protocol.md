# Подготовка кабинных пар по паузам и исправленным сценариям

Задача: проверить дополнительные потери при подготовке BLeRIOT. Это новая
подготовка слабого train, не обучение модели и не приёмочный ASR benchmark.

## Данные и устранённые ошибки

В первоначальных 476 окнах есть 362 train (338 исходных и 24 шумовые копии)
и 114 dev (102 исходных и 12 шумовых копий). Для новой подготовки используются
только девять исходных train-записей. Повторно использованы все 675 ранее
подготовленных клипов по паузам из `pair-quality-v1`, общей длительностью
107.6447 минуты. Аудио и исходные интервалы этих клипов не меняются.

Сценарии исправлены отдельно от аудио:

- Нумерация вида `3 - TRQ` распознаётся как номер пункта, а `100 %`, `1.5 bar`
  и значения в тексте команды сохраняются.
- Колонтитулы с ревизиями и моделями самолётов отделены от тела чек-листа.
- Для сканированных A320 pilote и PC7 проверены изображения страниц. OCR по
  отдельным областям сохранён как промежуточный результат; из-за оставшихся
  ошибок строки дополнительно извлечены ассистентом по изображениям. Это
  **машинная транскрипция документа**, не человеческая разметка речи.
- Сохраняются исходные SHA-256 PDF/DOCX, изображения, прежний OCR и новые строки.
  Из исходных файлов ничего не удаляется.

## Новый способ получения обучающего текста

Повторно используются 675 закреплённых small/English ответов. Выполняются
675 новых ответов исходной medium.en, CUDA/float16, beam 5, previous-text context
выключен. Модель видит только аудио. Документы, эталоны и старые ответы ей не
передаются как prompts, hotwords или иные текстовые входы.

Текст кандидата — **полный неизменённый ответ medium.en на клип**, а не сплошной
кусок печатного сценария. При отборе используется отдельная нормализация поиска:
регистр, пунктуация, фиксированный список сокращений (`rwy`/`runway`, `gnd`/`ground`
и другие) и написание букв акронимов. Она не изменяет ответы ASR и не заменяет
нормализатор WER в оценке моделей.

Условия зафиксированы до нового распознавания:

- Не менее двух слов. При числе слов меньше восьми два ASR-текста должны
  совпасть после нормализации поиска; для остальных допускается ≤15% расхождения.
- Последовательности чисел и ключевых отрицаний/состояний (`on/off`, `up/down`,
  `left/right`, `open/closed` и т. п.) должны совпадать между моделями.
- Не менее 90% слов ответа должны находить поддержку в ограниченном участке
  сценария, включая все найденные критические токены. Для короткой реплики
  требуется непрерывная последовательность, а не совпадения в разных местах.
- Медиана модельных оценок слов каждой модели ≥0.6, допустимые временные
  интервалы, не более 25% слов с нулевой длительностью. Начало слова в нуле
  по таймкодам Whisper само по себе больше не означает отказ: клипы уже
  выделены по паузам с записанными исходными координатами.

Это правила согласия машинных источников, не доказанные границы истинной ошибки.
Модельные вероятности не калиброваны. Оба ASR относятся к Whisper и могут делать
одинаковые ошибки. При изменении нормализации поиска или порогов нужна отдельная
версия подготовки; результаты текущего опыта не перезаписываются.

Новый train — отдельный вариант из неперекрывающихся клипов. Его не следует
механически складывать с прежними 49 окнами: они относятся к тем же записям.
Dev из 35 прежних пар сохраняется побайтно и в отбор новых train-пар не входит.
Разделение проверяется по говорящим, сессиям, исходным записям и хешам аудио.
Новый train-policy явно допускает только слабые машинные тексты с происхождением;
они не могут пройти как human_verified и не используются для сертификации качества.

## Воспроизведение

```powershell
docker compose -f compose.publisher-phrases.yaml run --rm prepare
docker compose -f compose.publisher-phrases.yaml run --rm infer
docker compose -f compose.publisher-phrases.yaml run --rm assemble
```

Первая команда требует подготовленных документов. Исторический OCR-проход
выполнен `scripts/prepare_publisher_documents_v2.py` в локальном образе
`north55-annotation-tools:0.1.0`; входы — `publisher-expanded-v1/documents` и
`bleriot-documents/v1`, выходы — `reports/publisher-phrases-v2/documents`.
Визуальные извлечения закреплены в `configs/publisher_visual_lines_v2.json`.

Команды подготовки/экспорта не перезаписывают готовую версию. Завершённый infer
проверяет хеши и не повторяет ASR. При первоначальной фиксации плана PowerShell
переформатировал дату в сведениях о весах, из-за чего первый запуск остановился
до единого ASR-ответа. Исходная строка восстановлена Python без изменения правил;
неудачная попытка и оба исправления до inference сохранены.

Полная причина недостатка кабинного качества этим опытом не устанавливается.
Прочитанные чек-листы не заменяют спонтанный разговор экипажа, а рост числа
обучающих пар сам по себе не означает улучшения распознавания.
