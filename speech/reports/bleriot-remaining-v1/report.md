# Что ещё мешает использовать BLeRIOT

Повторная проверка показала две разные проблемы: часть исходных train-записей
вообще не проходит в подготовку, а для выбранных записей печатный чек-лист
ошибочно рассматривается как дословная расшифровка. Доработка только порогов
согласия Whisper этого не решает.

Этот этап — разбор причин и проверка вариантов на сохранённых train-ответах.
Новых принятых обучающих пар, ASR-вызовов и шагов обучения в нём нет.
Прежние 96 пар и добавка из 59 сохранены без изменений.

## 1. За пределами 476 и 675 осталось почти 47 минут

В исходном train BLeRIOT-A **27 записей / 161.48 минуты**. Последние подготовки
брали только **9 записей / 114.51 минуты**, потому что `FAMILIES` в
`scripts/expand_publisher_pairs.py` содержит четыре семейства английских чек-листов.

Оставшиеся **18 записей / 46.97 минуты** не оценивались этим способом вообще.
Для **16 записей / 44.53 минуты** уже есть непустые издательские документы.
Для Puma2 и unknown, вместе 2.44 минуты, вместо расшифровки поставщик дал `Unknown`.
Вычисления выполнены только по train, без переноса dev/test.

Это CVR, радиообмен и Puma. Старое исключение радиообмена больше не соответствует
разрешённому пользователем расширению до авиации. Однако документы показывают
существенную долю французского и смешанного FR/EN текста. **Это не 47 минут
дополнительного английского.** Язык и содержание отдельных аудиофрагментов ещё
нужно установить; medium.en не подходит для всей этой части корпуса.

Готова [очередь исходных записей](omitted-source-queue.json) с путями, хешами,
говорящими, документами, языковыми предположениями и следующим действием.
Старый список отказов сохранён как история, а не изменён задним числом.

## 2. Чек-лист содержит поля и инструкции, а не все произносимые слова

На изображении страницы A320 pilote явно видны незаполненные поля:
`FUEL QUANTITY ___ KG/LB`, `BARO REF ___ (BOTH)`, `T.O SPEEDS & THRUST ___ (BOTH)`.
Там же встречаются ответы, которые должны произнести оба участника, и заголовки
этапов. Источник:
:codex-file-citation{path="C:/DEV/MIPT/Diploma/Speech/data/input/bleriot/verified/a/raw-speech_transcript/BEA_checklist_A320_pilote.pdf" purpose="source"}.

Конкретный клип `15a289085b978b309fb5597b1a44b3ce`, sp006, начало 18.744 с:
оба машинных текста содержат скорости `134, 135, 140`. Все проверки, кроме
поддержки документом, пройдены. В PDF эти значения отсутствуют, поэтому текущий
отбор отвергает клип. Отсутствие значения в незаполненном шаблоне не доказывает
ошибку распознавания. Согласие моделей также не доказывает правильность числа.

Для sp006 не принят ни один из 16 клипов. В ответах встречаются заполненные
поля, повторные ответы и `checklist completed`, которых нет в дословном виде
в сценарии. Одновременно там есть реальные расхождения и подозрительные слова,
например `gear pits` и `adios`. Нельзя объявить все 16 правильными после одной
поправки. Нужен шаблон пунктов: постоянный текст, тип переменного значения,
возможный повтор ответа и порядок прохождения. Значения следует проверять по
аудио, не выдумывать из PDF и не заменять по правдоподобию.

## 3. Неучтённые сокращения всё ещё мешают

На неизменённых 201 клипе с исключительно документальными отказами проверен
фиксированный список из 15 преобразований для поиска: например, `pwr/power`,
`avail/available`, `T/O/takeoff`, `cmd/command`, `norm/normal` и `turnoff/turn off`.
Тексты ASR, согласие между моделями, числа, вероятности, таймкоды и пороги
не изменялись. **21 клип / 3.86 минуты** стал проходить проверку документа.

Это измеренный эффект изменения сопоставления, а не 21 прослушанный эталон.
Результат сохранён в [сравнении сокращений](alias-comparison.json); новая версия
обучающего набора из этих кандидатов здесь не собиралась. Список выбран после
просмотра train-ошибок, поэтому это диагностический опыт, не независимая оценка.

## 4. При отказе целого клипа теряются совпадающие реплики

В **144 отклонённых клипах** найдены непрерывные последовательности минимум
из четырёх нормализованных слов, одновременно совпадающие в small, medium.en
и документе. В таких последовательностях суммарно **1026 слов**. Это
консервативный поиск целых совпавших блоков, не оценка всего пригодного текста.

Сейчас отказ одной части исключает целый клип. Следует выделять отдельные
реплики и повторно проверять их аудиограницы. [Найденные части](supported-subphrases.json)
пока не имеют такой привязки, поэтому число 144 нельзя считать числом готовых пар
или переводить в минуты готового обучения. Эти клипы могут пересекаться с 21
кандидатом после раскрытия сокращений.

## Что не оказалось главным объяснением

- VAD не отложил ни одного слишком длинного речевого интервала. Из 114.51 минуты
  выбранных оригиналов клипы занимают 107.64 минуты; остаток включает удалённые
  паузы и края. Без проверки аудио нельзя называть все 6.86 минуты потерянной речью.
- Шумовые версии C не добавляют независимых слов. В train есть 20 версий /
  55.62 минуты, 19 с акустически подтверждённым родителем. Они могут помочь
  акустической адаптации после подготовки текста оригиналов, но их нельзя
  прибавлять к объёму новой уникальной речи.
- Повторное нарезание одних записей увеличивает число строк, но не разнообразие
  говорящих и ситуаций. Издатель описывает BLeRIOT как чтение сценариев; даже CVR
  здесь не следует автоматически считать записью спонтанного разговора экипажа.

## Приоритет дальнейшей работы

1. Для нынешних английских записей ввести шаблоны чек-листов с переменными
   полями, раскрытием сокращений и последовательным сопоставлением пунктов
   в пределах записи. Это исправляет причину, по которой правильный текст
   может не пройти проверку документа.
2. Использовать найденные совпадающие части отклонённых клипов для нарезки
   отдельных реплик с проверкой границ. При проверке по аудио приоритет отдать
   числам, отрицаниям и неподдержанным словам, а не размечать всё с нуля.
3. Включить пропущенные CVR/радиосценарии через многоязычную подготовку и
   разделение языков. Сначала английские и смешанные фрагменты CVR1/CVR5;
   французский материал учитывать отдельно, без обещания переноса на EN/RU.
4. После привязки текста использовать соответствующие шумовые версии для
   обучения устойчивости, сохраняя группы исходных записей.

Для доказательства улучшения всё равно нужна проверка модели на независимой
разметке. Согласие двух Whisper фильтрует часть ошибок, но не измеряет истинную
точность, особенно на трудных акцентах и числах.

## Воспроизведение и проверка

`docker compose -f compose.bleriot-audit.yaml run --rm audit`

Скрипт не перезаписывает готовый аудит. Проверены хеши всех 675 small и 675
medium ответов, сохранность текста medium и соответствие популяций. Исходные
данные подключены только для чтения, сеть отключена, аудио/модели для этого
пересчёта не требуются. Ruff пройден. Новых основных модулей и правил допуска
обучения этот этап не меняет.
