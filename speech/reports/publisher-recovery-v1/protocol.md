# Повторная проверка окон BLeRIOT, отклонённых только по языку

Причины отказа всех 476 окон разобраны по сохранённым решениям. Из 408 отказов
108 относятся только к автоматической метке языка: 91 train и 17 dev.
Метка `fr` встречается и у черновиков, в основном состоящих из английских пунктов
чек-листов. Это основание для повторной проверки, но не доказательство ошибки
детектора на всех таких записях. Французские вставки остаются возможны.

Второй распознаватель — исходная Whisper medium.en, CUDA/float16, beam 5,
без сценария, подсказок и эталонного текста на входе. Выполняется один проход
по всем 91 train-окнам, включая связанные шумовые варианты. Параметры отбора
зафиксированы в `inference/plan.json` до новых ответов модели.

Новое правило допуска слабых обучающих пар:

- Старое окно относится к train и отклонено только по языку. Все прежние
  требования к привязке, числам, вероятностям и временным отметкам оно прошло.
- Сценарий содержит не менее восьми слов; расхождение второго распознавателя
  с этим **неизменённым** текстом по lexical edit distance не превышает 15%.
- Последовательности чисел после прежней диагностической нормализации и
  отрицаний совпадают. Это проверка согласия, а не разметка критических сущностей.
- Медиана модельных вероятностей слов не ниже 0.6, таймкоды допустимы.
  Модельные вероятности не считаются калиброванной достоверностью текста.
- Шумовая копия допускается только при наличии её чистого родителя в train.

Это **изменение правила отбора для нового обучающего набора**, а не исправление
исторического результата. Прежний запрет по метке языка заменён дополнительной
проверкой согласия с другой моделью; язык по аудио человеком не подтверждён.
Оба распознавателя относятся к Whisper и могут делать одинаковые ошибки.

Проверочные 17 language-only окон не переносятся в train. Прежний dev из 35 пар
копируется побайтно. Все остальные причины отказа на этом этапе остаются
неразрешёнными. Итоговые пары имеют статус weak, область read_cockpit остаётся
неподтверждённой, человеческая разметка не создаётся. Старые источники,
пользовательские ревизии, пороги приёмки и результаты не изменяются.

Этот этап измеряет число восстановленных обучающих пар. Он не обучает модель,
не выбирает новый ASR-профиль и не доказывает улучшение кабинного WER.

Команды из корня проекта:

```powershell
docker compose -f compose.publisher-recovery.yaml run --rm prepare
docker compose -f compose.publisher-recovery.yaml run --rm infer
docker compose -f compose.publisher-recovery.yaml run --rm assemble
```

Подготовка и экспорт не перезаписывают существующую версию. Повторный `infer`
проверяет хеши завершённых ответов и не запускает ASR повторно.

Источники: `data/curated/publisher-expanded-v1/`; готовый новый набор:
`data/curated/publisher-recovery-v1/train.jsonl` и `dev.jsonl`.
Пути аудио в манифестах относятся к прежнему Docker volume
`north55-speech_audio_data`; записи не копируются и не обрезаются заново.
