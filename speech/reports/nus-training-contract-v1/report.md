# NUS: что делать с уже имеющимися расшифровками

**Готовые обучающие пары имеются и уже использованы. Требовать от пользователя
переписывания всего корпуса оснований нет. Техническая проверка обучения — PASS;
проверенная смена режима декодирования ухудшила train WER и отклонена.**

## Что выполнено

| Проверка | Результат |
|---|---|
| Все 675 train-пар: hashes, длительность, канал, waveform | PASS, librosa/soundfile побитно совпадают |
| Признаки WhisperProcessor и faster-whisper | PASS, max abs difference 5.186e-5 при заранее заданном допуске 1e-4 |
| Язык, task, конец labels и отсутствие усечения | PASS: 475 EN, 200 RU; максимум 120 токенов и 27.84 с |
| Повторное восстановление base + сохранённый адаптер | PASS, все 479 сохранённых тензоров точно совпали на CUDA FP32 |
| Ошибка предсказания токенов на 32 фиксированных train-парах | Parent 1.9194 → NUS 1.4188 |
| Те же тексты с подставленными чужими записями | Parent 4.8588; NUS 4.4907; правильное аудио лучше в 31/32 случаях для обеих моделей |
| Самостоятельное распознавание всех 275 NUS без timestamp tokens | 550 GPU-ответов, 0 runtime failures |
| Тесты защиты inputs, путей и сохранения результатов | 4 passed |

Teacher forcing получает правильные предыдущие токены из train. Эти значения
не являются WER и не доказывают качество на новых записях. Чужие аудио выбраны
циклическим сдвигом фиксированного списка, не по ответам модели. Сравнение не
подтверждает человеческую точность текста или кабинную область каждого клипа.

## Проверенная гипотеза

В обучающих labels присутствует `<|notimestamps|>`, тогда как обычный runtime
распознаёт и временные метки. На тех же сохранённых весах и CUDA float16 изменён
только `without_timestamps`; остальные effective options, включая word timestamps,
оставлены прежними. Использован немодифицированный цикл faster-whisper.

| WER на 275 собственных train-парах, 967 слов | Обычный режим | Без timestamp tokens |
|---|---:|---:|
| Parent | 63.08% | 152.43% |
| NUS LoRA | 51.50% | 143.95% |

Для NUS число вставок выросло с 174 до 1066, улучшились 8 клипов, ухудшились 242,
25 не изменились. WER может превышать 100% из-за вставок. Этот режим не включён.
Это не независимая оценка и не новый поиск release candidate. Все исходные
эталоны и ответы сохранены; ошибки не исключались и текст не исправлялся.

## Ошибка первоначальной диагностической проверки

Первый `contract` остановился на слишком строгом сравнении CPU-слияния адаптера
с результатом исходного CUDA-слияния. Отдельно измерены все 72 изменённых тензора:
максимальная разница CPU FP32 — 1.4901161193847656e-08, CUDA FP32 — **0**,
CUDA TF32 — 1.0086223483085632e-06. В `contract-retry` устройство приведено к
исходному CUDA FP32; точное равенство сохранено как критерий. Веса не менялись.
Исходная ошибка и код остаются в отчёте; поправка — `contract-amendment.json`.

## Что это меняет в следующих действиях

1. Сохранить NUS как существующий обучающий источник с оригинальными текстами.
   Не объявлять все пары ошибочными по одному несогласию с Whisper; автоматическое
   несогласие остаётся диагностическим сигналом. Полной сверки по аудио здесь не было.
2. Следующую гипотезу адаптации проверять на сходимость обучения: фиксированный
   небольшой train-поднабор, ограниченное число шагов, одинаковый decoder и
   измерение самостоятельного train WER по ходу обучения. Успешное запоминание
   своих примеров подтвердит способность рецепта усваивать пары, но не перенос.
   Этот следующий опыт здесь **NOT_RUN**, дополнительных шагов обучения было **0**.
   Выбор шага по train не может выбирать release. Увеличение эпох само по себе
   не обещает исправить наблюдавшееся ухудшение кабинного dev.
3. Для утверждения об улучшении нужен независимый от обучения и прежней настройки
   набор целевой речи с человеческими расшифровками и группами исходных записей.
   NUS после обучения нельзя переименовать в независимый test; общая речь не
   доказывает качество разговора экипажа. Пользователь не обязан сам размечать
   весь train: можно использовать готовую проверенную разметку источника.

Первопричина плохого переноса полностью не установлена. Проверены и не подтвердились
гипотезы о перепутанном языке, усечении labels, отличающемся waveform, неверно
сохранённом адаптере и полезности простой смены timestamp mode. Это не исключает
ошибок в части исходных пар, недостаточной сходимости или несоответствия источников.

**Статусы:** implemented / executed / verified для перечисленных технических
проверок; проверенный способ улучшения — **FAIL**; независимые доказательства
ASR/сущностей/NLP/temporal — **NEEDS_MORE_DATA**. Прежний release gate **FAIL**
не меняется. Никакого подтверждённого качества RU/mixed cockpit не добавлено.
