/goal Реализуй на Python самостоятельный модуль north55_speech для проекта «55 Север» строго по SPEC.md и ACCEPTANCE.yaml; источники и ограничения данных — в SOURCES.md. Не ограничивайся планом, scaffold или заглушками: нужны работающий код, Docker Compose, тесты, воспроизводимые эксперименты и документация.

Сначала изучи существующий репозиторий и AGENTS.md, сохрани пользовательские изменения, зафиксируй assumptions и checklist. Область — речь экипажа и инструктора внутри кабины/тренажёра, НЕ pilot–ATC радиообмен. Поддержи EN/RU/mixed, различая техническую поддержку и фактически подтверждённое качество каждого языка.

Собери FastAPI с минимальной UI, Celery, RabbitMQ, PostgreSQL/Alembic, volumes для аудио/моделей/артефактов, CPU Compose и GPU override. Реализуй загрузку → очередь → проверку аудио/каналов → VAD → локальный Whisper через faster-whisper → безопасную нормализацию → эпизоды → обучаемый классификатор событий/значимости и извлечение сущностей → review → журнал и экспорт. Добавь адаптер локальной диаризации с явной обработкой отсутствующих весов, audit trail, таймкоды оригинала, отмену/retry и восстановление после сбоя. После явного получения весов inference должен работать локально без обязательных внешних API.

Главный результат — не просто запуск Whisper, а доказанное улучшение. Зафиксируй разумный baseline и сравни с candidate на той же ASR-модели/precision. Реализуй ablation и ограниченный dev-search: VAD/chunking, domain hints, denoise, повторное распознавание сомнительных мест; обучаемый NLP и отдельный запускаемый путь ASR LoRA при доступных данных/GPU. Активируй в выбранном pipeline только этапы с подтверждённой пользой.

Импортируй только проверенные и разрешённые данные; при недоступности конкретного корпуса обеспечь universal local importer и annotation workflow. Разделяй train/dev/test по speaker/session/оригиналу: clean/noisy-копии не попадают в разные splits. Не используй test-ответы в prompts, словарях, обучении, настройке или выборе candidate. Заморозь конфигурацию до final test.

Обязательная исследовательская цель: минимум 10% относительного снижения lexical WER, статистическое подтверждение, отсутствие ухудшения критических сущностей и clean-control сверх допуска ACCEPTANCE.yaml. Для NLP — отдельное сравнение с rules и проверка precision/recall/F1. Человеческие event labels нельзя подменять метками собственных правил; utterance classification нельзя выдавать за temporal event detection. Никогда не исправляй fifty в fifteen по «здравому смыслу», не приписывай роль по голосу и не выдавай произнесённую команду за фактическое состояние самолёта.

Доведи доступные этапы до исполнения и проверь CPU E2E, реальные ASR smoke-tests, отказоустойчивость и quality gate. Не ослабляй baseline/пороги и не выдумывай результаты ради PASS. Если эффект не подтверждён или не хватает независимых данных/разметки/GPU, выдай точный FAIL/INCONCLUSIVE/NEEDS_MORE_DATA/BLOCKED, сохрани все измерения и заверши независимые части. Не объявляй ML-задачу выполненной без доказательств и не продвигай candidate в release без необходимых gate PASS. Итог: код, проверенные команды PowerShell/Linux, реальные отчёты, статусы implemented/executed/verified и конкретные ограничения.
