# Передача задания Codex

Этот пакет содержит **техническое задание**, а не уже реализованный сервис или обученную модель. Benchmark пока не выполнялся.

## Файлы

| Файл | Назначение |
|---|---|
| SPEC.md | Полная спецификация: 21 основной раздел, архитектура, pipeline, данные, эксперименты, API, тесты и приёмка |
| ACCEPTANCE.yaml | Исходный машиночитаемый контракт quality gate; его parser должен реализовать Codex |
| CODEX_GOAL.txt | Готовая команда `/goal`, менее 4000 символов |
| SOURCES.md | Проверенные технические источники и честные ограничения проверки датасетов |
| START_HERE.md | Этот порядок передачи задания |

## Как начать

Создай рабочую папку модуля, например `north55-speech`, и распакуй в неё содержимое архива. Открой Codex в этой папке. Скопируй **всё содержимое CODEX_GOAL.txt**, начиная с `/goal`, и отправь как одну команду.

Для существующего репозитория можно положить SPEC.md, ACCEPTANCE.yaml и SOURCES.md в рабочую папку Codex рядом с кодом. Не перезаписывай существующие одноимённые файлы без резервной копии. Если размещаешь пакет в отдельной подпапке, исправь три относительных пути в `/goal` на реальные; содержание требований менять не требуется.

Короткой команды без SPEC.md недостаточно: детальные контракты и критерии находятся в файлах. Собственный AGENTS.md проекта сохраняется; новый этот пакет не навязывает.

## Что Codex должен построить

Локальный Python-модуль анализа разговоров внутри кабины/тренажёра, не ATC: API/UI, очередь обработки, Whisper + улучшающие кандидаты, диаризация как дополнительный адаптер, NLP, журнал с прослушиванием и ручной проверкой, Docker Compose CPU/GPU и воспроизводимый экспериментальный стенд.

Базовая исследовательская цель — минимум 10% относительного снижения lexical WER с подтверждением на независимом test и без недопустимого ухудшения критических сущностей/чистой речи. Это target разработки, не заранее известный результат. Отдельно проверяются классификация и значимость эпизодов.

## Как понимать результат

`ENGINEERING PASS` означает работающий и проверенный код в указанной среде. `ASR/NLP QUALITY PASS` дополнительно требует настоящих измерений на достаточных независимых данных. При отсутствии подходящих записей/разметки допустим результат `NEEDS_MORE_DATA`, но недопустима выдуманная таблица улучшений.

Все численные пороги — предложенный исходный протокол для проекта, не нормы университета или авиационной отрасли. Изменять протокол допустимо до заморозки и просмотра final-test результатов, сохраняя rationale/version; нельзя ослаблять его после измерений ради PASS.

Доступы к закрытым датасетам/моделям, подтверждение прав на записи и настоящее GPU-железо не создаются текстом задания. Codex должен проверить реальные возможности среды, продолжить независимые части реализации и отдельно обозначить ограничения.
