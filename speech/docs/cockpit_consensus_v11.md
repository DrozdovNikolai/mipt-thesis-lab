# Локальное распознавание с согласованными исправлениями

Экспериментальный профиль сохраняет прежний ответ Whisper/Parakeet и исправляет отдельные слова, только когда Parakeet и Canary предлагают одинаковую правку в одном и том же месте. Сильный шум обслуживается прежним Parakeet; русская речь — прежним Whisper. Автоматического переноса таких текстов в обучающую разметку нет.

Для английского кабинного аудио в PowerShell 7:

```powershell
./scripts/Invoke-CockpitConsensusV11.ps1 -AudioDirectory C:/Audio -Files recording.wav -OutputName recording
```

Для нескольких файлов из той же папки: `-Files first.wav,second.wav`. `-Language ru` пропускает английские модели, `-Language auto` сохраняет прежнее автоопределение языка Whisper в английском маршруте. Указывайте новое имя результата для каждого запуска.

Выходы находятся в `reports/cockpit-consensus-v11/local-runtime/output/`: `recording.json` содержит итоговый текст и явный список исправлений, `recording-base.json` — исходные ASR-ответы и их временные метки. Если слово исправлено, старые метки не выдаются за выравнивание исправленного текста. При наличии правок итог нормализован по словам, без исходной пунктуации. Исходная расшифровка сохраняется.

Один файл должен длиться от 0,025 до 30 секунд; длинные записи не обрезаются автоматически. Входы монтируются только для чтения. Оба этапа работают без сети: сначала прежний NeMo 2.4/Whisper, затем Canary в отдельном NeMo 2.5. Это сохраняет совместимость прежнего распознавателя и ограничивает одновременную загрузку GPU. Установлены локальные pinned веса; основной API-профиль не переключён.

## Что измерено

[Первоначальный отчёт](../reports/cockpit-consensus-v11/report.md) использует 541 прежний вход: новые ответы Canary из v10 и сохранённый Parakeet. [Отдельная проверка одиночного режима](../reports/cockpit-consensus-v11/runtime-validation/comparison.json) заново распознаёт все 491 английский вход Parakeet с batch=1 и применяет то же правило. Это необходимо: на одном smoke-фрагменте прежний batch=4 вернул пустую строку, а одиночный режим — слова. Исходные результаты не переписаны.

[Протокол](../reports/cockpit-consensus-v11/protocol.md) фиксирует два варианта до их оценки; выбран вариант одинаковых отдельных правок. Простое полное совпадение двух расшифровок не прошло критерии. [План](../reports/cockpit-consensus-v11/plan.json), [верификация](../reports/cockpit-consensus-v11/verification.json), [проверка команды на шести файлах](../reports/cockpit-consensus-v11/local-runtime/verification.json).

Эталоны остались прежними: пять частичных ручных и 35 слабых dev. Один и тот же dev участвовал во многих опытах. Шумные копии не добавляют независимых дикторов. На части train-записей консенсус ухудшает ответы: одинаковая ошибка двух ASR возможна. Диагностический выигрыш здесь не подтверждает независимую приёмку SPEC.

## Повторение

Для нового каталога с зафиксированным планом:

```powershell
docker compose -f compose.cockpit-consensus-v11.yaml run --rm infer
docker compose -f compose.cockpit-consensus-v11.yaml run --rm report score
docker compose -f compose.cockpit-consensus-v11.yaml run --rm report verify
```

Завершённые артефакты защищены от перезаписи. Для повторного подсчёта нужны локальные входы, ответы и эталоны, исключённые из Git; для нового ASR также нужны существующие model/audio volumes. Полученные выводы не являются независимо размеченным датасетом.
