# Сложные фрагменты и новая очередь разметки

Подготовлен `data/curated/cockpit-hard-v4`: 247 пар, 29.06 минуты с учётом
16 шумовых копий. Оригинальная речь — 27.60 минуты, 9 дикторов. Из 377 кандидатов
добавлены 25 сложных пар, 15 прежних нарезок заменены пересекающимися полными
фрагментами. Все обучающие тексты остаются слабыми машинными расшифровками.

352 отклонённых кандидата сохранены в `reports/cockpit-hard-v4/decisions.json`.
Первые 60 отобраны в очередь проверки с ограничением количества на исходную запись.
Новые 42 контрольных отрывка выбраны по времени из 7 dev-записей, без отбора по
результатам моделей. Они покрывают 3 прежних dev-диктора и не пересекают прежние
35 слабых dev и старый пакет ручной разметки. Test не использован.

## Ручная проверка

[Открыть локальную разметку](http://localhost:8011). Используется прежний ключ
разметки. Старый интерфейс на порту 8010 и его ревизии сохранены отдельно.

Сначала полезно заполнить 42 строки `dev`: это 7 минут аудио. Прослушать весь
отрывок, записать услышанное, указать язык и область речи. Числа и отрицания
переписывать по аудио. Неразборчивое не угадывать; использовать отметки
неразборчивости или оставить расшифровку неподтверждённой. По просьбе пользователя
для этих 42 фрагментов добавлены необязательные черновики Whisper large-v3 с
автоматическим определением языка. Кнопка «Подставить машинный черновик» заполняет
пустое поле; уже введённый текст не затирается. Отметить прослушивание и подтвердить только действительно
проверенные поля, затем сохранить.

Черновики находятся в `assisted-drafts`, разрешение на их просмотр — в
`draft-policy.json`. Исходные manifests, старые заглушки и ревизии сохранены.
Просмотр записывает модель и SHA-256 черновика в `draft-exposure`. После сохранения
такая расшифровка получает `machine_draft_exposed=true` и
`reference_method=human_corrected_machine_draft`, даже если человек подтвердил текст.
При оценке это проверенная человеком расшифровка с машинной подсказкой;
её нельзя называть слепой независимой расшифровкой. Само наличие черновика
ещё не означает, что разметчик его видел. Галочки проверки автоматически не ставятся.

Подготовка черновиков отдельно от обучения:
`docker compose -f compose.annotation-drafts.yaml run --rm generate`, затем
`docker compose -f compose.cockpit-hard-v4.yaml restart review`.

В 60 строках `train` по кнопке черновика доступны ответы small, medium.en и
large-v3. Их нужно сверять с аудио, особенно числа, on/off, up/down и отрицания.
Открытие подсказки фиксируется. Само открытие или сохранение текста не должно
считаться независимой ручной проверкой. Все исходные строки очереди имеют
`transcript_status=missing`; пользовательские изменения сохраняются ревизиями.

Весь пакет занимает 16 минут аудио; время на расшифровку будет больше времени
прослушивания. Экспорт train и dev доступен в интерфейсе. Результаты разметки
не подмешиваются в уже замороженное обучение и не меняют старые метрики.

## Выполненный эксперимент

Три режима с одинаковыми 247 парами и порядком предъявления: decoder+KL,
decoder CE без KL, encoder+decoder CE. По 240 реальных обновлений, BF16,
исходный Whisper-small, LoRA rank 8, LR 2e-5. Общие начальные матрицы декодера
совпадают побайтно. Последний checkpoint каждого режима задан заранее.

[Протокол](../reports/cockpit-training-v4/protocol.md) ·
[Результаты](../reports/cockpit-training-v4/report.md) ·
[Проверка подготовки](../reports/cockpit-hard-v4/verification.json)

Команды выполняются из корня проекта. Сначала подготовка:

```powershell
docker compose -f compose.cockpit-hard-v4.yaml run --no-deps prepare
docker compose -f compose.cockpit-hard-v4.yaml run --no-deps infer
docker compose -f compose.cockpit-hard-v4.yaml run --no-deps assemble
docker compose -f compose.cockpit-hard-v4.yaml up -d review
```

Для исследования: `python -m scripts.run_cockpit_training_v4 STAGE [ARM]`.
Стадии: `freeze`, `init`, `tests`, `train`, `convert`, `baseline`,
`candidate ARM`, `cpu ARM`, `score`. ARM: `decoder-kl`, `decoder-ce`, `full-ce`.
Подготовка/обучение/конвертация защищают существующие результаты от перезаписи.
Повторный inference проверяет идентичность и использует сохранённые ответы.
Для нового эксперимента нужны новые каталог и том; старый опыт изменять нельзя.

Модели сохранены в Docker volume `north55-speech_cockpit_training_v4`, в
`models/whisper-small-cockpit-hard-v4-{decoder-kl,decoder-ce,full-ce}`.
Адаптеры и состояния оптимизатора — в `training/checkpoint-{ARM}`.
Вычисление использовало отдельный том; рабочая модель не заменялась.
