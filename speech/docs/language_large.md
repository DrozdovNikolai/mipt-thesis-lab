# Проверка указанного языка и large-v3

14 сентября 2026. Две проверки, явно запрошенные пользователем, выполняются по
[замороженному протоколу](../reports/language-large-v1/protocol.md).
[Измеренный отчёт](../reports/language-large-v1/report.md) и
[исходные тексты пяти фрагментов](../reports/language-large-v1/human-fragments.md)
сформированы из сохранённых ответов после завершения обоих прогонов.

## Измеренный результат

| Набор | Прежний small | Small с языком | Large-v3 с тем же языком |
|---|---:|---:|---:|
| 5 пользовательских dev-эталонов, 115 слов | 34 ошибки / 29,57% | 16 / 13,91% | 20 / 17,39% |
| 50 общих чистых EN controls | 3,62% | 3,62% | 6,10% |
| 50 общих RU controls | 9,55% | 9,55% | 5,21% |

Передача EN уменьшила lexical WER на **52,94% относительно**, 95% paired CI ΔWER
**[−0,282609; −0,065217]**, 2000 повторов / seed 55 / 3 группы. Это изменение
языковой информации на небольшом dev-наборе, а не независимая исследовательская приёмка.

Large-v3 против small с тем же EN дала **на 25% больше ошибок** на пяти фрагментах,
CI ΔWER **[0; 0,086957]**. Чистый EN ухудшился на 2,47 процентного пункта при
допуске 1 п.п. Шум VOICI: **11,0381 → 46,4593 слов/мин**; BLeRIOT-B:
**7,9479 → 19,9509 слов/канало-мин**. Эти диагностические ограничения — FAIL.
Улучшение RU и слабых смесей указано отдельно и не компенсирует неудачные проверки.

Исполнены **1322 свежих GPU ASR вызова, ошибок 0**; 656 small-ответов на неизменённых
языковых режимах побайтово совпали по тексту с прежними. Large-v3 прошла 3 CPU
smoke-вызова без сети с фактическим `int8_float32`, за 29,65 с с загрузкой.
**12 тестов и 40 проверок артефактов прошли**, качество для release — NEEDS_MORE_DATA.

На 11 562,26 с аудио small затратил 556,39 с ASR, large — 542,60 с. Общий RTF
0,0481 / 0,0469 зависит от состава набора: на пяти человеческих фрагментах large
медленнее (0,0405 против 0,0139), на общем EN — 0,0736 против 0,0274.
Наблюдённый общий GPU peak — 4176 / 7410 MiB; CPU RSS — 1160,4 / 3255,0 MiB.

## Дизайн

Используются те же 661 вход: 114 BLeRIOT dev окон (35 слабых эталонов),
5 прежних пользовательских dev-расшифровок, 50 LibriSpeech EN и 50 FLEURS RU
контролей, 204 фиксированные смеси VOICI, 151 VOICI и 87 BLeRIOT-B шумовых каналов.
Число аудиозаписей не означает число независимых эталонов или говорящих.

В сохранённых пяти пользовательских ревизиях язык — EN, область и прослушивание
подтверждены пользователем. Прежний исследовательский driver явно передавал
`auto`, одинаково для baseline и candidate. Новый опыт проверяет передачу EN
из этих метаданных. Остальные 656 языковых режимов остаются прежними; слабый
издательский английский сценарий не превращается в подтверждение языка аудио.

- `small_previous`: 661 прежний ответ, неизменные hashes и происхождение.
- `small_known`: 661 новый вызов того же parent small CUDA/float16; отличается
  языковая информация только для пяти ранее проверенных фрагментов.
- `large_known`: 661 новый вызов large-v3 CUDA/float16 с точно теми же входами
  и языковой информацией, что у `small_known`.

Сравнение 1 меняет языковую информацию, сравнение 2 — checkpoint. Ни одно не
является доказательством улучшения pipeline при одних и тех же checkpoint и
входной информации. Это 2 новых конфигурации, исчерпывающие записанный бюджет 16.
Поиск новых вариантов, дообучение и изменение порогов здесь не выполняются.

Whole-clip ASR, beam 5, temperature 0. VAD, denoise, hints и re-decode отключены.
Роли, критические значения и состояние самолёта не выводятся из этих сравнений.
Новые GPU вызовы последовательны, что позволяет сравнить время свежих запусков.
Прежние ответы используются для эффекта языка, но не для сравнения скорости моделей.

## Веса и воспроизводимость

Получена [SYSTRAN CT2-конверсия large-v3](https://huggingface.co/Systran/faster-whisper-large-v3),
лицензия MIT, revision `edaa852ec7e145841d8ffdb056a99866b5f0a478`.
Все 6 файлов проверены по publisher LFS SHA-256 / Git blob SHA-1.
`model.bin` размером 3 087 284 237 bytes имеет SHA-256
`69f74147e3334731bc3a76048724833325d2ec74642fb52620eda87352e3d4f1`.
Manifest находится в volume моделей, каталог `whisper-large-v3-systran-ct2`.
Глобальный model lock и production baseline не перезаписаны.

В `reports/language-large-v1/frozen` сохранены 108 файлов исполняемого кода,
конфигураций и требований. Inference-контейнеры получают только frozen code,
новый каталог inputs/outputs и read-only volumes аудио/моделей. Старые отчёты
и `/scoring/references.json` им не смонтированы; сеть отключена.

Команда последовательных GPU запусков, реально использованная на PowerShell:

```powershell
./scripts/run_language_large.ps1
```

Имена контейнеров сохраняются. Повторное создание через эту команду отвергается;
для намеренного восстановления незавершённого запуска используются:

```powershell
docker start -a north55-language-small-v1
docker start -a north55-language-large-v1
```

Восстановление проверяет frozen plan, options и hashes; готовые записи не
пересчитываются. В этой версии принудительное прерывание ради теста не выполнялось.

Пересчёт готовых ответов не требует GPU или сети:

```powershell
./scripts/language_large_report.ps1 score
./scripts/language_large_report.ps1 report
./scripts/language_large_report.ps1 verify
```

Linux с теми же данными и Docker volumes:

```sh
sh scripts/language_large_report.sh score
sh scripts/language_large_report.sh report
sh scripts/language_large_report.sh verify
```

`score-reproduction.json` фиксирует фактически выполненные PS/Linux команды,
exit codes и побайтовое совпадение: **PowerShell и WSL Ubuntu score исполнены,
SHA-256 совпали**. PowerShell report/verify выполнены; Linux report/verify
отдельно не запускались. Renderer/verifier смонтированы отдельными файлами `/app`;
они не меняют inference и scorer. Verification выполняется после формирования
всех артефактов.

Первый CPU контейнер не стартовал: Docker не смог создать новый bind-mount файл
внутри read-only frozen scripts. Ошибка сохранена в `cpu-attempt1-mount-failure.json`,
контейнер — как `north55-language-large-cpu-attempt1-v1`. Frozen файлы не изменялись.
Исправлен путь монтирования helper; следующая попытка прошла. GPU ASR не затронут.

Групповой флаг интерпретируемости замороженного scorer проверяет лишь число групп:
при двух BLeRIOT-B noise-группах он true, хотя WER CI отсутствует (пустые эталоны,
valid_resamples=0). `ci-interpretation.json` явно даёт false для этого случая, RU
и одногрупповых смесей. Метрики, scorer и replay сохранены без изменений;
статистическая значимость WER на шуме не заявлена.

RTF относится к ASR или исследовательскому driver, без очереди/UI. Инициализация
измеряется отдельно. GPU память опрашивается через nvidia-smi с целевым шагом
0,5 с: это общая память устройства с другими приложениями, не точный объём
выделения модели. CPU RSS относится к памяти процесса. Точность CPU smoke
отдельная от CUDA/float16 сравнений и не подменяет их.

Слабые сценарии, воздействие подсказок на пять dev-ревизий, отсутствие размеченных
критических сущностей и независимого final test сохраняют общий статус
`NEEDS_MORE_DATA`. Даже благоприятное число WER здесь не продвигает модель в release.
