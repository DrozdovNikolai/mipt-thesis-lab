## Выполненный ASR опыт

661 вход: прежние 524 плюс 87 каналов BLeRIOT-B и 50 RU controls.
Пять систем дают 3305 записей сравнения. 524 прежних parent-ответа повторно
использованы с проверкой аудио/config/options/hash, с явной ссылкой на происхождение.
Это не объявлено новым исполнением ASR. Остальные 2781 запись отражают новый
запуск стадий, включая выход без ASR, если VAD не нашёл речи. Фактическое число
вызовов модели и сохранённых исключений находится в `asr/comparison.json`.

Baseline: прежний pinned parent Whisper-small CT2, CUDA/float16, beam 5,
temperature 0. Все системы получают одинаковую информацию о языке, без prompts
и hints. Сравниваются прежнее разбиение VAD, gate без разбиения, span с сохранением
внутренних пауз и запасом 400 мс с краёв, gate + существующий denoise strength 0.3.
Не добавлены повторные распознавания и не изменены числовые значения текста.

Во всех вариантах доступны исходные ASR ответы, слова и таймкоды, интервалы
VAD/переданные модели интервалы, параметры, ошибки и происхождение reused baseline.
План фиксируется до inference. Это исследовательские варианты в отдельном driver;
рабочая конфигурация API не меняется. Дополнительных новых pipeline designs три,
прежний VAD segments повторяется; суммарный бюджет остаётся в пределах 16.

Метрики считаются отдельно для слабых издательских эталонов, пяти прежних
человеческих dev-расшифровок, EN/RU общих контролей, смесей и шума. Для шума
пустой эталон — допущение на основании описания издателя, не новое человеческое
подтверждение. BLeRIOT-B измеряется в суммарных канало-минутах, без представления
их как независимых полётов. Одногрупповой bootstrap не выдаётся за статистическую
значимость. Данные критических сущностей и независимый кабинный final test
по-прежнему недостаточны для release PASS.

Полученные измерения: gate + denoise даёт **33 вместо 34 ошибок из 115 слов**
на пяти пользовательских dev-эталонах: WER **28,70% против 29,57%**, относительное
снижение **2,94%**. Paired cluster bootstrap 95% CI ΔWER **[−0,043478; 0]**:
требуемые 10% и статистическое подтверждение не получены. VAD segments ухудшает
WER до 65,22%; gate и span оставляют 29,57%. На общей RU речи baseline 9,55%,
gate + denoise 9,23%; на чистом EN оба 3,62%.

На VOICI gate уменьшает вставленные слова с 11,0381 до 0,0398 на минуту;
на BLeRIOT-B — с 7,9479 до нуля на канало-минуту. Эти шумовые диагностики
проходят численные допуски, но не подменяют отсутствующую проверку сущностей
и независимый кабинный final test. Фактически выполнены **4022 новых вызова ASR**;
**980** результатов VAD пустые и не вызывали модель. Исключений ASR **0**.

## Выполненный NLP опыт

До обучения и чтения текстов для разработки зафиксировано разделение по case ID.
Используются только `analysis_data=1`, разговорные строки, явно указанный CVR,
источник CAM/HOT/INT, документированная роль Captain/First Officer/Flight Engineer,
без явного радиоадресата. RDO/ATC, неопределённый канал, отсутствующая метка и
пустой текст исключаются с сохранением чисел и причин. Отбор канала основан на
метаданных, а не голосе; независимая человеческая проверка области не заявлена.

Получено 3281 реплика: **2838 train / 394 dev / 49 holdout**, **24 / 7 / 1 случая**.
Метка `coding_safety_voice` взята напрямую у человеческих кодировщиков;
проектные `labels`, `salience`, `temporal_events` оставлены пустыми.
Дополнительные строки с пустым полем исходного аудиоканала не добавлялись ради
размера набора или улучшения метрик.

Реально обучен TF-IDF word/char + logistic regression. Проведены 9 заранее
заданных C/threshold trials, затем 3 опыта с предыдущей репликой. Контекст не
перескакивает через исключённые строки и не использует будущий текст, метки,
факты аварии или роли как признаки. Два baseline: существующие project hazard
rules и более широкие фиксированные hazard rules. Все trials сохранены.

Dev macro-F1: project rules 0.5576; broad rules 0.5853; классификатор без контекста
0.5893; с контекстом 0.6042. Последний выбран до holdout inference и заморожен.
На 49 репликах одного holdout-случая его macro-F1 0.5000 против broad rules 0.6449;
precision/recall/F1 класса safety voice: 0.1111 / 0.2000 / 0.1429.
Дальнейшая настройка по этому holdout запрещена.

**NLP — INCONCLUSIVE:** выборка одного случая не позволяет оценить обобщение,
а наблюдённый результат уступает широким правилам. Ни этот label, ни классификация
реплики не подменяют проектную разметку эпизодов или temporal detection.
Сохранённый локальный `model.skops` работоспособен; его scores не считаются
калиброванными вероятностями. В рабочий классификатор он не установлен.

## Проверки и воспроизведение

15 новых контрактных тестов проверяют отбор радио/неизвестного канала, сохранность
контекста и временной шкалы, отсутствие будущих реплик/меток в признаках.
Реальное CPU исполнение нового RU/noise материала прошло с фактическим
`int8_float32`. Результаты инженерных проверок отделены от quality gate.
Исторический полный CPU E2E и recovery не выдаются за повторно выполненные.

Сохранён точный исполнявшийся код в `reports/additional-sources-v1/frozen`:
105 файлов Python, config, требований и lock. Это позволяет воспроизводить
результаты после изменений рабочей копии. Renderer/verifier в командах ниже
накладываются отдельно: их изменения не меняют исполненную модель, декодирование
и frozen scorer. В частности, сортировка import в рабочем ASR driver выполнена
после сохранения его исходных исполнявшихся байтов.

PowerShell, из корня репозитория:

```powershell
./scripts/additional_sources_report.ps1 score
./scripts/additional_sources_report.ps1 report
./scripts/additional_sources_report.ps1 verify
```

Linux, с теми же данными и Docker volumes:

```sh
sh scripts/additional_sources_report.sh score
sh scripts/additional_sources_report.sh report
sh scripts/additional_sources_report.sh verify
```

Реальный Linux запуск проверен через WSL Ubuntu:

```powershell
wsl -d Ubuntu -- sh /mnt/c/DEV/MIPT/Diploma/Speech/scripts/additional_sources_report.sh score
```

PowerShell score/report/verify и Linux score исполнялись. Linux report/verify
отдельно не повторялись. Score повторно использует записанные ответы, без GPU и
скачивания; verification фиксирует hashes, поэтому её следует запускать последней.
Нужен CPU image `north55-speech:login-fix-v1` и прежние volumes аудио/моделей.
Совпадение PowerShell/Linux отчётов проверяется побайтово.

Фактические команды и mounts GPU/CPU/NLP контейнеров сохранены в
`reports/additional-sources-v1/north55-*.json`; журналы рядом. Для незавершённого
ASR процесса можно использовать `docker start north55-additional-asr-v1`:
готовые ответы не пересчитываются, несовпадение runtime/plan отвергается.
После форматирования рабочей копии восстановление требует замороженного driver,
поэтому для нового контейнера следует монтировать `frozen/scripts` и `frozen/src`.

Команды получения, реально выполненные на Windows, сохраняют оригиналы и
проверяют уже загруженные файлы:

```powershell
python -X utf8 scripts/acquire_bleriot_b.py
python -X utf8 -m scripts.acquire_fleurs_ru
python -X utf8 -m scripts.acquire_cvr_noort
```

Для CVR supplementary ZIP URL, HTTP status, размер и SHA-256 находятся в
`data/input/cvr-noort-v1/acquisition.json`. Source XML/codebook и исходный ZIP
сохранены. `acquire_cvr_noort` воспроизводит получение и metadata-only partition;
в этой сессии его повторная проверка сохранённых файлов выполнена без изменений.
Заданный SHA — hash полученного и проверенного экземпляра, не checksum издателя.
Для повторного скачивания при отсутствии файла нужна сеть. Импорт:
`python -X utf8 -m scripts.prepare_cvr_native`, только для новой версии каталога,
без перезаписи замороженной подготовки.

Один первоначальный сбой генерации отчёта распаковки BLeRIOT-B (absolute/relative
path) сохранён в `bleriot-b-attempt1.json`; исходные архивы были корректны. После
исправления выполнена новая распаковка в отдельный `verified/b-v1`, без удаления
первого вывода. Этот сбой не скрыт и не относится к ошибке распознавания текста.
