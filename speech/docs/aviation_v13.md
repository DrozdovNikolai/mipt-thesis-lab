# Большая проверка ASR и расширенная очередь разметки

Этот этап сравнивает фиксированные кабинные профили v9/v11 на всех 1901 уже
загруженных фрагментах ATCOSIM с издательскими расшифровками. Обучения и подбора
порогов здесь нет. ATCOSIM содержит имитацию речи диспетчеров, четыре диктора;
результат не объединяется с кабинными метриками. Опубликованная test-часть ранее
использовалась локально как dev, поэтому новым закрытым тестом она не считается.

Результат на всей выборке: v9 — 67,18% WER, v11 с описанной ниже защитой —
57,34%, прежний Whisper small — 69,66%, специализированный ATC Whisper —
12,11%. При прежней симметричной нормализации чисел: 47,97%, 45,69%, 50,82%,
17,97% соответственно. Пять отказов генерации сохранены в результатах;
все 1901 записи включены в подсчёт. Для этого диспетчерского корпуса
специализированная ATC-модель остаётся лучшей из сравниваемых.

Прежние ответы Whisper small и специализированного ATC Whisper проверяются по
хешам исполнения v1 и используются повторно. v9 и v11 распознают все записи
заново. Машинные подсказки для ручной разметки не становятся эталонами.

## Запуск и проверка

Первоначальная фиксация входов: `python scripts/prepare_aviation_v13.py`.
Существующий пакет она не перезаписывает. План, входы, эталоны, версии моделей,
метрики и драйвер фиксируются хешами в `reports/aviation-v13/plan.json`.
Протокол подсчёта и хеш `scripts/score_aviation_v13.py` находятся отдельно в
`scoring-protocol.json`; скрипт проверяет их до подсчёта.

```powershell
./scripts/Run-AviationV13.ps1
```

Сначала выполняется повтор прежних 16 записей; полное совпадение полей
результатов проверяется до большого запуска. Затем последовательно проходят
все 1901 вход: Whisper/Parakeet и Canary/согласование. Драйвер добавляет только
сохранение и возобновление отдельных результатов к неизменённым вычислениям
замороженных скриптов. При повторном запуске сохранённые записи проверяются
по идентичности плана, кода, профиля и аудио. Несоответствие останавливает прогон.

Прогресс: `io-full/hybrid-progress.json`, `io-full/consensus-guarded-progress.json`.
Логи лежат рядом. Подсчёт требует всех входов, проверяет каждый checkpoint и
сверяет расстояние редактирования независимым алгоритмом. Обычная пунктуация
и регистр игнорируются. Числа отдельно оцениваются существующей симметричной
нормализацией. Основная метрика — корпусный WER, а не среднее по фрагментам.

Итог: [отчёт](../reports/aviation-v13/report.md),
[агрегаты](../reports/aviation-v13/comparison.json),
[проверки](../reports/aviation-v13/verification.json).
Сырые тексты, checkpoints и замороженная копия кода остаются локальными.

Исходный v11 остановился на седьмой записи ATCOSIM: Canary достиг лимита
генерации 256 токенов. Первоначальные план, лог и шесть успешных результатов
сохранены. `generation-guard-plan.json` фиксирует отдельный вариант: при этом
конкретном отказе сохраняется гипотеза v9, отвергнутый ответ Canary и причина
отказа. Другие исключения по-прежнему останавливают процесс. Ни слова эталонов,
ни новые пороги для этой защиты не использовались. Успешные вычисления не меняются.

`Run-AviationV13.ps1` при наличии этого дополнения вызывает
`Run-AviationV13Guard.ps1`. Последний сначала воспроизводит 16 сохранённых
успешных результатов, затем проверяет искусственный отказ с продолжением
обработки, после чего проходит всю большую выборку. Проверочные воспроизведения
используют сохранённые ответы ASR, без новых вызовов моделей. В таблице результатов
этот вариант называется **v11 + fallback к v9**. Полного WER исходного v11 у
прерванного исполнения нет; все отказы учитываются отдельно. Метрики и список
входов остались прежними; предыдущий протокол подсчёта сохранён в
`scoring-protocol-original.json`.

## Разметка

Старая очередь на порту 8011 сохранена: 42 dev-фрагмента и 16 человеческих
расшифровок. Новая очередь на порту 8012 содержит 84 дополнительных окна по
10 секунд — все оставшиеся кандидаты прежней сетки 10/15 секунд из семи dev
записей, без прежнего ограничения «шесть на запись». Это ещё 14 минут,
но те же три диктора. Всего в двух очередях 126 фрагментов.

```powershell
docker compose -f compose.annotation-expanded-v13.yaml up -d review
```

[Открыть 84 новых фрагмента](http://localhost:8012/?split=dev).
Кнопка «Подставить машинный черновик» заполняет пустое поле. Существующий текст
не заменяется. Прослушивание и подтверждения остаются ручными; сохранение
фиксирует происхождение от машинной подсказки. Оценка языка используется только
для порядка: 28 предполагаемых английских первыми, 56 предполагаемых французских
далее. Встречаются ошибочные определения языка; все записи доступны.

Новый пакет отделён, чтобы не менять идентификаторы групп старого пакета и
историю его ревизий. Проверка: `python scripts/verify_annotation_expansion_v13.py`.
[Аудит](../reports/aviation-v13/annotation-verification.json) подтверждает
сохранность 202 прежних файлов и наличие всех 84 черновиков. Закрытый кабинный
test не открывался. Подтверждённые пользователем новые записи нужно включать
в следующую версию оценки, сохраняя текущие результаты неизменными.
