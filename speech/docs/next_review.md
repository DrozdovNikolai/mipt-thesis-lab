# Следующее действие: проверить готовые тексты по аудио

Начните с одного фрагмента, а затем пройдите фиксированный список ниже.
Для этого шага нужны только текст, язык и область записи. Категории событий,
значимость и сущности можно оставить неподтверждёнными: их отсутствие не мешает
сохранить проверенную расшифровку для ASR.

1. Откройте http://127.0.0.1:8010/ во встроенном браузере, Chrome или Edge.
   Введите своё имя и значение `NORTH55_API_KEY` из `.env` в корне проекта.
   Ключ вводится только в локальную форму, отправлять его в чат не нужно.
2. Выберите `bleriot-a:BEA_checklists_sp001`, окно оригинала **30–50 секунд**.
   Если проверенного текста ещё нет, издательский текст подставится автоматически.
3. Прослушайте все 20 секунд. Сверьте каждое слово, исправьте только то, что
   действительно слышно. При повторном прослушивании обращайте внимание на числа,
   отрицания и слова, которые читатель добавил или пропустил относительно сценария.
4. Выберите фактически слышимый язык и область. Для чтения чек-листа предусмотрено
   «Чтение кабинного сценария». Отметьте «Область и язык проверены по аудио»,
   «Каждое слово сверено с аудио» и «Я прослушал(а) весь фрагмент» только после проверки.
5. Нажмите **«Сохранить новую ревизию»**. Продолжите по списку.

Если слово или число нельзя разобрать, не подтверждайте весь текст как проверенный.
Сохраните доступную часть без этого подтверждения; спорный фрагмент остаётся в
пакете. Автоматическая подсказка может ошибаться даже при успешной привязке.

В UI также остаются четыре Puma-окна из первоначального пакета. Для текущего
английского эксперимента они не требуются: соответствующий издательский сценарий
французский. Файлы не удаляются, язык аудио автоматически подтверждённым не считается.

После сохранения напишите в чат «готово» или укажите, какие фрагменты проверены.
Далее агент проверит реальные ревизии, экспортирует допустимые train/dev и
пересчитает сравнение по человечески проверенным расшифровкам. Это следующий
пилотный dev-результат; он ещё не заменяет независимый final test нужного объёма.

Результаты предыдущего эксперимента сохраняются отдельно. Существующие ревизии
не перезаписываются, а событийному NLP не присваиваются метки из правил или текста
сценария. Полная инструкция: [review_packet.md](review_packet.md).
